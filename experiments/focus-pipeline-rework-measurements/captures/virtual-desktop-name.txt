The virtual desktop's name

Taken on 2026-10-29 on Windows 11 build 26200 (x64), in session 1, with NVDA alpha-58022,732d1ce2 (the pin) running and recorded through cargo xtask nvda capture's `--wait-file` step (eSpeak NG, default symbol and verbosity levels), since the capture refuses keys once its window has left the front, which a desktop switch and Task View do. keys.ps1 (this folder) pressed the keys with SendInput. winevent-hook.ps1 (this folder), an out-of-context WinEvent hook on every process, recorded EVENT_OBJECT_NAMECHANGE (0x800C) for the window GetDesktopWindow() (65548, class #32769), with the raising thread's process, the window's InternalGetWindowText and, from the second run on, its client object's MSAA accName; a second instance recorded every EVENT_SYSTEM_FOREGROUND (0x0003). Times are microseconds since the Unix epoch. The machine had two desktops, both unnamed, at the start.

What it shows. Every desktop switch (Windows+Control+D, Windows+Control+Left and Right), the rename in Task View, and each closing by Windows+Control+F4 raises exactly one name change on the desktop window, always from thread 1152 of csrss.exe (process 980, session 1; Win32_Thread names the thread's process, since the hook cannot open the thread), 25 to 140 ms after the switch's foreground event. The desktop window's text, InternalGetWindowText, is empty every time; the virtual desktop's name is the desktop window's client object's MSAA accName ("Desktop 1", "Desktop 2", "Rework Desk"), which is what NVDA says ("Desktop 3", "Desktop 2", "Rework Desk"), once per switch, and nothing else for an empty desktop. The rename raised the event at the Enter that committed it, and NVDA said "Rework Desk" before the list item's "Rework Desk 4 of 4". The event's object is OBJID_WINDOW (obj=0), whose accName NVDA takes as obj.name (nvda/source/eventHandler.py 338 to 346); the window object's accName is the same "Desktop 1" as the client's (combo-box-drop-down.txt, the chain's last two entries). A process-scoped hook would therefore be scoped to csrss, and the name must be read through MSAA, not the window text. Every Windows+Control+Left or Right also raises a foreground change, for explorer's "Virtual desktop hotkey switching preview" window (class VirtualDesktopHotkeySwitcher), and Windows+Control+D a second one for Program Manager; Windows+Control+F4 raises none. With a window shown on all desktops in front (Notepad 3541188, pinned with Task View's "Show this window on all desktops"), a switch raises the same foreground change for the switching preview and none for Notepad, which is still the foreground window afterwards (GetForegroundWindow), and NVDA says only the desktop's name, not Notepad.

Two slips during the run, both undone: on the new, empty Desktop 3, Task View's first Tab went from the desktop list to its "New desktop" button, so F2 did nothing, the typed text went nowhere, and Enter added and switched to a fourth desktop; the rename was then done on that fourth desktop (F2 on its list item). Cleanup closed the fourth and the third desktops with Windows+Control+F4 and returned to Desktop 1; the registry then listed the two original desktops, unnamed, with Desktop 1 current.
