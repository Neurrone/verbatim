Two child dialogs of one role and name

Taken on 2026-10-30 on Windows 11 build 26200 (x64), NVDA alpha-58022,732d1ce2 (the pin) in session 1, started from a scratch configuration with eSpeak NG, defaults, the update check off and the transcript add-on, through cargo xtask nvda capture; then, with NVDA closed, Verbatim at 10c9e83a (target\debug, VERBATIM_TEST_AUDIO=null, eSpeak NG) through cargo xtask nvda capture --verbatim, the same steps. The window is two-same-named-dialogs.ps1 (this folder), a Windows Forms form "Two dialogs capture" holding two panels, each a child window of its own whose MSAA client object (OBJID_CLIENT) is role dialog, name "Remove", the first holding a "First" button and the second a "Second" button, each button a child window of its panel; window-ancestry.ps1 (this folder) read the chains below while the NVDA run's form was open. mockapp could not give this setup: its child-window command makes one child window that serves the whole fixture tree from its root, and its focus command raises EVENT_OBJECT_FOCUS only from the host window, so no node can be a dialog that is a child window of its own with the focus event raised from a window inside it.

What it shows. Tab from the first dialog's button into the second's, a second dialog of the same role and name with a different window handle in the same top-level window, NVDA says "Remove dialog" again, then "Second button", and again each time the focus crosses between the two panels (Shift+Tab back, Tab forward). NVDA treats the two windows as two containers, as the test two_windows_with_one_role_and_name_are_two_containers (crates/verbatim-core/tests/reduce.rs) expects. Verbatim at 10c9e83a says only "Second button" and "First button" on those moves, and does not say "Remove dialog" again, so in this application it still enters the two dialogs as one container; the dialog nodes here are the panels' client objects, reached from each button's window by the walk, and presumably carry no window handle, so Core falls back to matching by role and name. At entry NVDA did not say the form's title, and Verbatim said "Two dialogs capture" first; the lines before the front step in Verbatim's run are its own console window and log, spoken as Verbatim started, and are not part of the setup.
