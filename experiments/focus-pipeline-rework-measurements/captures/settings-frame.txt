The Settings frame

Taken on 2026-10-30 on Windows 11 build 26200 (x64), NVDA alpha-58022,732d1ce2 (the pin) in session 1, started from a scratch configuration with eSpeak NG, default symbol and verbosity levels, the update check off and the transcript add-on, through cargo xtask nvda compare settings_system_page and cargo xtask nvda capture (the compare report's date is UTC). settings-frame.ps1 (this folder) read the windows from the focus up to the desktop while the Display page was open; NVDA's developer info (NVDA+F1) gave its objects for the two windows named Settings, reached by object navigation from the focus.

What it shows. Entering a Settings page from another window, whether launched from the desktop (ms-settings:display) or brought forward from a Windows Forms window, NVDA says "Settings", then "Settings window", then the entered groupings and the focus; moving within the page (Tab, Shift+Tab, Up and Down Arrow) it says only the entered groupings and the focus, and nothing for either window. The two windows are ApplicationFrameHost's frame (ApplicationFrameWindow, 28640960) and, inside it, SystemSettings' content (Windows.UI.Core.CoreWindow, 20187504). The frame's InternalGetWindowText is "Settings"; its MSAA window object (OBJID_WINDOW) is named "Settings" with role window (9), and its client object (OBJID_CLIENT) is named "Settings" with role client (10); UIA gives it as a Window named "Settings". The bare "Settings" is the frame's client object, role client mapped to pane (IAccessibleHandler/__init__.py 77), a role silent on focus (controlTypes/role.py 536 to 549), presented by its title as a top-level client with a system menu (NVDAObjects/IAccessible/__init__.py 2095 to 2106): NVDA speaks it as the focus, from the frame's own MSAA focus on its client, when its foreground defer finds the frame in front, and otherwise as an entered ancestor of the content's focus, the object its UIA parent step makes for the frame's window (experiments/the-settings-frame-comes-in-front-after-its-foreground-event/nvda-capture.txt, which replaces this capture's first account of it). "Settings window" is the CoreWindow, a UIA window, spoken as an entered ancestor. Object navigation up from the focus reaches a different object for the frame, an IAccessible WindowRoot (OBJID_WINDOW) named "Settings" with role window (the developer info below), and names it "Settings window".
