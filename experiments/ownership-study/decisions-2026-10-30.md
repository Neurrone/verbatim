# Dickson's decisions, 2026-10-30 (to fold into the design and architecture docs)

- A window's title is always said when the focus comes into it, so the speech does not depend on event order (a deliberate difference from NVDA, whose own result depends on pump timing). Supersedes the earlier batch rule of the same day.
- A repeat focus is read in full and judged in Core; the reader never drops it alone and holds no copy of Core's focus.
- The application rules (applications.rs refuses_focus, the app's in_ignored_window) stay where they are until M5 moves them (D6).
- The CoCancelCall experiment for UIA client calls, from M6.1, is run now.
- Implementation stays paused until the race problem is addressed by the architecture change.
- The ownership model covers all of Verbatim and the planned milestones (extensions, caret rework and later), not only the focus path; its refactor is built in a separate session against its design document, and this session resumes after it.
- No change for its own sake: each change the model proposes must show a benefit to safety or clarity, naming the defect it would have prevented or the race or confusion it removes; parts already compliant stay as they are.
- Refined criterion: a change points to a concrete past defect, or shows the concrete future defects it would prevent; only then is it in scope.
- In the refactor: the settings store (one saver off the path, one writer per section), real-time audio rules and fixes, the synthesizer display name localized, the key number carried on the input, and review commands on the key reports' route into Core.
- The benefit criterion, refined later the same day: a change is in scope only when it points to a concrete past defect, or shows the concrete future defects it would prevent, as a sequence that would go wrong in today's code or a planned milestone. On that basis these are in the refactor: the settings store's shared mutex with the reducer writing the file under it (one saver off the path, one writer per section); real-time audio (the mixer lock held across WASAPI calls, the audio thread's per-pass lock and allocation), stated as a rule and fixed; the synthesizer's display name decided in the host without the locale; the key number carried on the input instead of the `KEY_ORIGINS` table; and review commands taking the same route into Core as key reports.
- The outpost's reducer runs on a thread of its own: workers run call programs and post results, the watchdog only posts timer inputs, and objects the reducer releases are handed to a worker. Its cost, one hop each way per call program and one more wake-up per event and result, is stated in `docs/performance.md`.
- Accepted defaults: M4.4's move of the message types is folded into the refactor's messages build; the gap record is kept as built; the supervisor's owner thread is not made a pure state machine now. The message types need not live in a platform-neutral crate if another placement makes the enforcement easier; the placement is chosen by the design.
