# Second review of docs/design/ownership.md: 5 Important

First-review findings 2, 3, 5, 7, 8 fixed; 1, 4, 6, 9 fixed in part with new defects below.

1. Core, title rule: the entered window is set from foreground_window on every report Core takes, but that field is read when the report is published (window_facts in event_message, worker.rs ~4811), not when read, so it can name a window the report is not in. Sequence: Windows Forms button b in form M has focus; Enter opens dialog D; the MSAA read of b is served by M's UI thread busy in ShowDialog and finishes after D is in front; b is published with top_level M, foreground_window D, in_foreground true (D's root owner is M); Core takes b, entered window becomes D, no title; D's foreground change and its focus d1 share a batch, newest-first drops the foreground change, d1's foreground_window D equals the entered window, D's title is lost. Fix: change the entered window only from a foreground report (to its own window) or a report whose own top-level window equals its foreground_window; add this sequence as a test.

2. Message kinds, configuration: "the relay writes a new generation in one pass of its one thread" does not exist and fails under the writer policy. Fetches is sent by the app thread through send_to_outpost (main.rs ~1808); on a full queue it is refused and retried after the next input; supervisor/writer.rs fails any "other" message at once when the queue is full; SetBackendOverride has no production sender. Sequence: the outpost's queue is full, the listener's not; generation 2 reaches the listener, which judges a focus under it, the relay routes that fact; generation 2's push to the outpost failed and is retried later, so the outpost receives a generation-2 judgement while on generation 1. Writing listener first then outposts from the app thread races the same way. Fix: name the mechanism (configuration through the relay thread, or written to every outpost before the listener) and its overflow policy ("always gets through, behind what was queued before it").

3. Identity during a walk, release rule: "a node minted but never recorded at a position is freed by the first release after its minting" frees nodes of a walk still running; today's take_releasable (outbound.rs 215) deliberately keeps never-reported nodes. Sequence: a worker walks an MSAA focus (~20 calls) and mints ancestors; Core's NodesHeld for an earlier position arrives on the next command write (often during rapid Tab); the release frees the walk's unrecorded ids; the walk's result or the bound's publication then publishes ids whose objects are gone; Core's focus, caret reads and targeting answer gone. Fix: free unrecorded nodes only when minted by a dead worker generation or a request already claimed; the store needs a mint tag (generation, request); add an in-flight walk crossing a release as a replay test.

4. Workers and call programs, the object store's home: called "today's registries in verbatim-uia and verbatim-ia2" while Recorded is a verbatim-outpost type whose constructor is private to the store's module; a constructor cannot be private to a module of another crate; verbatim-uia/src/client.rs and shape/shapes.rs mint directly (id_for_element); the registry's public retain(impl FnMut) runs a caller's closure under its lock; one node per window keyed by handle spans two registries and neither owns that map. Sequences: any module of verbatim-outpost or verbatim-uia holding a registry clone can mint or call retain with a closure outside the monitor; at the bound the shell mints a plain window for handle H, a later walk reaches H's UIA element and gets that node holding the plain-window object. Fix: name the store's crate and module; it owns both registries as private fields (privacy from ownership); walks get a store handle; say which object a handle-keyed node keeps when another kind of object for the same window is reached.

5. Where the message types live: verbatim-protocol's stated edges are wrong; protocol.rs and protocol/raw.rs use verbatim_process::transport (Parts, put_frame, read_frame, put_frame_with_raw, MAX_FRAME_BYTES) and verbatim_process::clock::now_us, and verbatim-process depends on windows; Message::from_parts takes Parts; turning messages into Core's inputs would add an edge. (Now superseded by Dickson's decision: the types go in verbatim_model::protocol; framing, encode/decode and now_us stay in verbatim-outpost. Restate the edges accordingly.)

## Nits
- Followed focus: the "only messages added" case also arises across processes in one top-level window (ApplicationFrameHost's outpost follows the frame while Settings' follows its control); harmless, one sentence.
- Title rule test comparing the chain entry's words with a foreground report's holds only within one backend; UIA chain entry against an MSAA window read can differ in name.
- keyboard-opened-context-menu.txt shows NVDA saying "Untitled - Notepad" on the first Escape from Windows 11 Notepad's context menu; the rule says no title; record it as a known difference or cite it.
- Merge equivalence needs a named projection; counters, caret history and text caches from the dropped older focus differ.
- Recorded and positions: positions are numbered at write (number()), so Recorded is marked at write time.
- Release as a program: say whether it runs under the watchdog's deadline; a final Release into a hung terminal blocks programs queued behind it on that worker.
- Console poll: the inbox wait must use the high-resolution timer caret_poll.rs relies on (recv_timeout waits at 15.6 ms); whether a release effect in the inbox makes the poll yield; how the old key's request is answered when a newer key ends its watch.
- OutpostMessage seal: Event is built in supervisor/frames.rs and the app's tests build NotWatched; restrict the seal to lifecycle variants and give tests a constructor behind a feature.
- SpeakToken must also cover speak_for_key, play_earcon (speaks words) and play_earcon_to_end; say how speech after the reducer stops at exit gets the token.
- The hook's allow-list check cannot tell a bounded crossbeam Sender from an unbounded one by path (the runtime assertion at lib.rs 496 holds it); it must skip #[cfg(test)] modules.
- The reducer's local reads are buildable only as an injected query trait like WindowQueries in acceptance.rs; say so (the acceptance test interleaves 5 to 10 local calls).
- Older-generation reads: the stated limit also covers a read made under an older generation, judged again and dropped, while the outpost's own MSAA event was skipped under the older generation.
