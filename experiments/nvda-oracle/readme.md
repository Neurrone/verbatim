# NVDA as an offline oracle

Whether NVDA's own code can run headless, with no desktop and no running NVDA, on a recorded or hand-built "world" served through stand-ins, so that its speech can be compared with Verbatim's. The rewrite's verification design rests on these results (`docs/design/rewrite/design.md`, "Verification"). Run on Dickson's x64 machine (Windows 11) on 2026-11-28, against NVDA alpha-58022, the build the pinned submodule names (732d1ce2).

Every experiment loads NVDA's source from `nvda/source` read-only and replaces modules and functions as NVDA loads; nothing under `nvda/` was changed. Paths to the session's scratch folder are redacted to `<scratch folder>`, and to this repository to `<repository>`. Left out: the Python environment, comtypes' generated modules, NVDA's per-run configuration folders, the IAccessible2 type library and other build output.

## Rerunning

- Python 3.13 (NVDA's `pyproject.toml` requires at least 3.13 and below 3.14), with comtypes 1.4.16, NVDA's pinned configobj, fast-diff-match-patch, regex and pyyaml.
- `NVDA_LIB` set to the installed NVDA's native library folder, `C:\Program Files\NVDA\lib\alpha-58022,732d1ce2\x64`, for `nvdaHelperLocal.dll`, `nvdaHelperRemote.dll` and `UIARemote.dll`.
- Replace `<repository>` in the scripts with this checkout's path.
- IAccessible2's type library is built by `text/build_ia2.py` with midl from Visual Studio's x64 tools; the IDL is now in the `nvda/include/ia2` submodule.

## The experiments

- `oracle2.py`, `focus_test2.py`: the first study. NVDA's speech layer runs headless on stand-in `NVDAObject`s with fixed properties and gives NVDA's focus, state, typing, review and terminal-diff speech; it needs the matching native helper, without which character review said "blank".
- `uia/`: NVDA's UI Automation handler, its object layer with overlay classes, File Explorer's app module and the speech layer run on stand-in COM objects for UI Automation. It matched a live capture for two focus events in Explorer (`target/captures-2026-11-20/s2-explorer-forms-output/f5-address-tab.jsonl`, not kept) and dropped a duplicate and a late focus by NVDA's own rules. Later inventories (`docs/design/rewrite/nvda-inventory/`) found nine defects in this harness that change speech: stubs that accept any call dropped delayed calls and 50 global commands, the capture point missed say-all, the silent synthesizer changed words, and the pump ran only the event queue. The design's harness rules come from them.
- `time/`: a simulated clock and a cooperative scheduler for NVDA's threads. NVDA's own core pump, compiled from `core.py` unchanged, runs on it; the caret watch (`editableText._hasCaretMoved`) detects a move at 40 ms by event and at 80 ms by bookmark and times out at 100 ms; the watchdog recovers from a stand-in call that hangs; a terminal's output depends on thread order (8 of 13 orders say "42", 5 say nothing, with no stabilising delay). NVDA's native UI Automation event limiter can be driven deterministically by holding its flusher; it keeps the older of two duplicate events (`nvdaHelper/local/UIAEventLimiter/rateLimitedEventHandler.cpp` 46 to 51). Its saved outputs (`out_rl.txt`) disagree with the model and are to be rerun before either is trusted.
- `text/`: a text model behind UI Automation's text interfaces, with NVDA's review and caret scripts over a Notepad world, matching all 25 steps of a live capture; NVDA's MSAA path with the real IAccessible2 definitions, matching a Run dialog capture except the dialog's description, which depends on children no recording held; Windows 11 remote operations, which change speech only in Word and heading navigation.
- `browse/`: NVDA's shipped `nvdaHelperRemote.dll` loaded into the test process with no injection, its native Chromium and Firefox buffer builder and live-region code and its Python browse mode run against stand-in IAccessible2 objects: page load, quick navigation, reading a line, focus mode and a live region.
- `native/`: a real hidden list-view control read through NVDA's list-view classes and in-process helpers; NVDA's display model with its drawing hooks installed in the test process only; the older input-method interface through its message hooks, and its reports to NVDA replayed with identical speech. The list-view item never reported focus, so focus was forced; the cause is noted in `lv.py`.
- `office/`: NVDA's native Word and Excel helpers run in the test process against stand-in object models, with NVDA's app modules on top; Word's remote-operation extensions run both in NVDA's local executor over a text model and through Windows' real UI Automation core against a provider registered in the test process (2.7 ms for one small program).

None of the native-code results (`browse/`, `native/`, `office/`) has yet been compared with a live capture, and in `native/` and `browse/` NVDA's code reached a live process and the real desktop window; the design counts them only after a no-leak check and a live comparison.
