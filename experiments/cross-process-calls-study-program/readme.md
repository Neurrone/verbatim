# The cross-process calls study's program

The one scratch program behind the experiments of `docs/design/cross-process-calls-study.md` (2026-10-29). Each experiment's own folder has its readme and its output; this folder has the code they share.

- `xproc.rs` is a mockapp test binary with no test harness, kept here and not built by the workspace. `XP_EXP` names the experiment it runs: `second_form`, `retire`, `search`, `hook`, `walk_race`, `acc_focus`, `register`, `compare` or `msaa_onward`. `XP_TRIALS` sets the trials per arm (6 unless said), and `XP_ARMS`, where an experiment reads it, the arms run. Every result line starts with `RESULT` and goes to stdout.
- With `XP_ROLE=helper` set, the binary is a helper: a separate UIA client process, driven over its stdin, that plays another process's part. It looks a window up by handle as an outpost does (`lookup`, the outpost's `window_element` with its node request, which applies the proxy rule), takes a window's element and sets UIA up in its process with one remote operation (`grab`), then makes a plain name read (`read`) or a remote operation reading the name (`op`) on it, raises a `WinEvent` (`notify`), or makes the listener's desktop-wide registration (`register`, `verbatim_uia::Registration::with_parts` with the listener's four parts over the desktop). A helper's waiting calls run on threads of their own, each with its own client, so it goes on taking commands.
- `scratch-support.patch` applies to b15ad7bf and adds what the program needs: its `[[test]]` entry in mockapp's `Cargo.toml`, and `spawn_shown` in the tests' `common` module, a mockapp spawned with `--show`. No mockapp command or behaviour was added.

The program uses the product's own code wherever a step is the product's: the outposts' lookup (`Uia::window_element`), the runtime-id search (`Uia::window_live` and `Uia::find_by_runtime_id`, as `resolve_uia_element` in `crates/verbatim-outpost/src/outpost/read.rs` makes it), the listener's reader (`OutpostUnderTest::listener_read`), the classic walk (`verbatim_uia_rops::focus_ancestry_classic`, given the listener's query), the outpost's handling of a fact (`OutpostUnderTest`), and the listener's registration. Where the product's order of two steps had to be forced, the program makes the first step, changes the window hierarchy or the focus, then makes the second, as `experiments/getfocusedelement-after-the-focus-moves/` did; each readme says which.

mockapp's hit counters are read through its window (`common::read_hits`, `common::read_get_objects`), after any stall has ended, since reading them is itself a sent message.

## Rerunning

Start at b15ad7bf or later. Apply `scratch-support.patch`, copy `xproc.rs` to `crates/mockapp/tests/`, and build with `cargo test -p mockapp --test xproc --no-run`. Run the binary it names with `XP_EXP` set; the experiments `acc_focus` and `register` take the foreground on the interactive desktop, so nothing else may use it while they run, and no other UIA client (NVDA, Narrator, a running Verbatim, an inspection tool) may run during any of them. The runs recorded were made on 2026-10-29 on Dickson's x64 machine (Windows 11, build 26200), debug build, at b15ad7bf with the patch.
