# Verbatim Development Guide

This guide is for people working on Verbatim itself: building it, testing it, and understanding how it works. It is arranged in four parts, after the Diataxis framework:

- **Tutorials** take a newcomer through a first piece of work, step by step.
- **How-to guides** say which command to type for a task already understood: setting up, running the end-to-end suite, measuring, debugging.
- **Reference** describes the crates, the testing standard, the test coverage, the costs of each operation and the faults found in UI Automation.
- **Explanation** gives the reasons: the architecture and its decisions of record, walkthroughs of a focus change, a key and an utterance across the processes, the design records of finished work, and the Windows background they rest on.

New to the project? Read [Architecture](explanation/architecture.md), then [Walkthroughs](explanation/walkthroughs.md), keeping [the glossary](reference/glossary.md) at hand; if the Windows accessibility APIs are unfamiliar, [Windows background](explanation/windows/readme.md) has a reading order.

The plans for work in progress, the NVDA parity ledger and the notes on how NVDA works are kept in the repository for the agents that build Verbatim, and are not published here; pages here link them on GitHub.
