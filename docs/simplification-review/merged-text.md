### B1. Three implementations of each UIA text read

Both reviewers. The entry point quoted by B is in `caret.rs` 583-591: `if !remote { return caret_read_classic(query).map(|answer| (answer, Path::Classic)); }` and `Err(error) => caret_read_classic(query).map(|answer| (answer, Path::Fallback(error))),`. The outpost's generic path exists for every `TextSource`, `UiaText` included (`text/uia.rs` 396-605 implements `caret`, `unit_at`, `move_by`, `text`, `offset_in`, `advance`, `compare`, `select`, `location`, `edges`), and runs when a source's at-once method answers `None` (`text/mod.rs` 541-544: "`None` for a source that reads them one at a time, which the caller then does, reading no formatting"). The selection-change rule is written three times, not four as B said: `emit_changes` (`caret.rs` 1462), `classic_changes` (`caret.rs` 2067, commented "as [`emit_changes`] judges it", 2079) and the outpost's `selection_changes` (`text/mod.rs` 1516); `classic_changes_since` (`text.rs` 1448) calls `classic_changes` (1467). Commit e380a0ce (28 files, +633 -159) edited the remote program and its twin (`caret.rs` +99, diff hunks at 1617 and 1876 of the old file) and the generic path (`held.rs` +131). Lines recounted: caret twin 42 + 458, text twin 408, watch twin 119, total about 1,027, every helper used only by twins (grep of `classic_runs`, `classic_caret`, `unit_at(`, `attribute_values` in `crates/verbatim-uia-rops/src`). Speech: the generic path reads no formatting today, and `UiaText::edges` answers `(false, false)` (`uia.rs` 598-601) where the caret twin reads whether a selection starts on the first line (`classic_first`, `caret.rs` 1993-2002); so a window read classically would lose formatting and that edge unless the generic path gains both reads (B estimated 60 lines for a `formats` primitive). It is a question because it changes the remote-operations crate's recorded shape ("Each algorithm is a named operation with a remote program, a classic implementation of the same signature ... and an entry point that chooses between them", `books/dev/src/reference/crates/verbatim-uia-rops.md` 17-20). A's note that the classic half of `uia_text_reads_moves_and_answers_caret_keys` already runs the generic path is wrong: `uia_notes(hwnd, false)` (mockapp `text.rs` 345) sets `UiaText::remote(false)`, which runs the uia-rops twins. The facts on every twin are in section 2a.

## 2a. The classic twins in `crates/verbatim-uia-rops/src/`, every one

What makes the classic path run, common to all: the outpost's `tries_remote` (`crates/verbatim-outpost/src/outpost/mod.rs` 573-582): `self.remote_operations && hwnd.is_none_or(|hwnd| { self.classic_windows().get(&hwnd) != Some(&verbatim_win32::window::window_thread(hwnd)) })`. `remote_operations` is the developer setting `uia.remote_operations` (`verbatim-config/src/lib.rs` 160-174, "for diagnosing a provider and for before-and-after measurements", on by default), passed as `--classic-uia` (`verbatim-outpost/src/main.rs` 51). A window enters `classic_windows` only when a run failed with `Error::Import` (`read_classically`, called at `text_reads.rs` 491-493 and 781-786, `read.rs` 940-943, 1698-1700, 2108-2111, 2270-2273, `completion.rs` 180-183, 449-452, `asked.rs` 887-890); the crate guide says an import fails for "An element served by a client-side proxy (UIA's MSAA proxy inside Verbatim's own process) ... with `E_UNEXPECTED`" (`verbatim-uia-rops.md` 121-123). Beyond that, each entry point falls back to its twin for one call on any other failed run.

Why the twins exist, from the record: introduced as "the fallback and the reference" (bca051bf, 2026-10-07: "A classic implementation behind the same signature makes the same reads call by call, as the fallback and the reference"; 389e8838, 2026-10-06, focus). 88a901f9 (2026-10-06): "A window whose element cannot be imported is read the classic way for its lifetime, a failed run falls back for that call". The crate guide: "NVDA declines remote operations before Windows 11, which Verbatim always runs on (and a Windows without the API fails per call, `Error::Unavailable`)" (`verbatim-uia-rops.md` 730-733), so no supported Windows version lacks them; "Not implemented: marking a window after repeated run failures" (727-728); a run past the instruction limit "would be answered classically for that call" (750-751). Architecture R3: remote operations on ARM64 are "still to be verified" (`architecture.md` 751-752, 1201-1205). No ADR or roadmap entry decides the twins; the roadmap's only mention is M6.5's "The caret read made with a focus chooses remote or classic reading by the previous focus's window ... only the read's cost differs" (`docs/roadmap.md` 1466). No document or commit names a real application whose import failed, and no test drives an `Error::Import` fallback (grep of `Error::Import` in `crates/mockapp/tests`: 0).
