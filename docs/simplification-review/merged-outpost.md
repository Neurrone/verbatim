### 1. "Probe first" answered with a probe the outpost did not make (Defect; Q1 for the ownership)

Verified path. `asked.rs` 64-72 sets `context.given_verdict` to `None` for `WindowVerdict::ProbeFirst`. `verdict` (asked.rs 286-309), on `ProbeFirst`: `let began_us = context.observed_now(); let uia = read::window_uses_uia(context, hwnd); probes.push(Probe { window: window_handle(hwnd), thread: …, provider: uia, began_us, });`. `window_uses_uia` (read.rs 159-168) returns the given verdict when there is one, else calls `crate::arbitration::uses_uia`, which calls `decide` (arbitration.rs 342): `match arbitrator.verdict_at(&verdicts, hwnd, &classes, at_us) { Some(true) => return Verdict::Uia, Some(false) => return Verdict::NotUia, None => … }`, with no probe when the outpost keeps a verdict. `verdict_at` (274-288) answers from the class lists and then `verdicts.kept_at(...)`, where `Probed::Uia` lasts the window's lifetime (`verbatim-reader-rules/src/verdicts.rs` 41-42, `matches!(self, Self::Uia | Self::Excluded)`) and a "no" lasts `NEGATIVE_VERDICT_LIFETIME_US` (500,000) from the probe's end (`arbitration.rs` 228-237, `self.observed_now().saturating_add(NEGATIVE_VERDICT_LIFETIME_US)`). The answer's probe is reported whatever happened. Core records it (`verbatim-core/src/focus/backend.rs` 234-252, "the newest probe's start wins") and keeps every verdict, yes or no, for `PROBE_LIFE_US` (500,000) from `began_us` (276-283). NVDA keeps both for half a second from before the probe: `now = time.time()` then `if not v or (now - v[1]) > 0.5: v = (self._isUIAWindowHelper(...), now)` (`UIAHandler/__init__.py` 1371-1378).

Sequences:
- A window with a provider (B's): at 0 s Core has no verdict and sends "probe first"; the outpost probes, keeps "UIA" for the window's life, and reports a probe begun at 0. At 2 s Core's verdict has lapsed and it sends "probe first"; the outpost answers from its keep and reports "provider, begun at 2 s", a probe it never made. NVDA probes again at 2 s. The backend is the same both ways, since a provider stays.
- A window with none (A's): at 0 s "probe first"; the probe waits 300 ms and finds none; the outpost keeps "no" to 0.8 s and Core keeps MSAA to 0.5 s. At 0.6 s Core sends "probe first"; the outpost answers from its keep with no probe and reports "no provider, begun at 0.6 s"; Core keeps MSAA to 1.1 s. NVDA probes at 0.6 s. A window whose provider appeared at 0.55 s is read through MSAA until the first request after 1.1 s, where NVDA reads it through UI Automation from 0.6 s.

The outpost's keep also serves every window a walk crosses (`read.rs` 226, 387, 542, 679, 1105, 1331, 1474, 1946, 2145, 2168, 2243), and only the request's own window's probe is reported; those other windows' verdicts are the outpost's alone. Removing the outpost's keep outright would therefore probe every crossed window on every request, where NVDA caches each for half a second.

The decisions of record do not agree with each other:
- ADR 0001, "One judge per fact (Dickson, 2026-10-29; amended 2026-10-30 and 2026-11-13)": "Each window has one backend verdict, its outpost's (class lists, then one raw probe, kept as NVDA keeps it)". The sentence dates from `df0700c2` (2026-11-08), before ADR 0003.
- ADR 0004 (decided 2026-11-18), "UI Automation candidates": "Core's backend cache is the one owner of a window's verdict; the check thread's probe record only spares a repeated probe and never ends a check (delegated)."
- `architecture.md` 498-503: "Which backend speaks for a window is a per-window verdict Core keeps, from NVDA's class lists or the probe a tell or a request carries … A request to an outpost on a window with no verdict in force carries "probe first", and its answer returns the verdict"; and 716: "Arbitration is Core's per-window verdict". But 902-905, under "Latency budget" ("per D15"), keeps "a verdict that a window has a UIA provider for the window's lifetime (a verdict that it has none is trusted for 500 ms, NVDA's cache period, then probed again …)", which is the outpost's rule, not Core's.
- `arbitration.rs` 72-75 reconciles them its own way: "These verdicts decide only how the outpost reads a window; which backend's events speak for a window is Core's judgement". No document of record states that split.
- `docs/design/readers-tell-core-asks-build1.md` 409: "every answer carries the probes the request made". The outpost breaks this.

So ADR 0001's sentence is contradicted by ADR 0004 and architecture.md 498 and 716; architecture.md 903 states a keep that only the outpost applies. The defect fix that needs no ruling: on "probe first", the outpost probes the request's window (bypasses its keep for that window), as build1 line 409 says. Whether the outpost keeps its own verdicts at all, and by whose rule, is Q1. B's note that `arbitration.rs` line 30's "as decision D15 specifies" is a wrong citation is half right: D15 (architecture.md 151-156) is the latency budget and says nothing of it, but the "Latency budget" paragraph citing D15 (893-905) does state the lifetime keep. Check run: the files and lines quoted; `grep -rn 'window_uses_uia\|own_window_uses_uia'` (18 call lines, all in read.rs and asked.rs).

### 2. The release's "live" list is always empty, so the store's tags decide nothing (Remove now; both)

Verified from every call site. `Effect::Release` is built in one place, logic `lib.rs` 677-684: `let live = self.live(); self.releasing = true; effects.push(Effect::Release { nodes, anchors, acknowledged, live, });`, inside `run`, whose only caller is `pump` (653), inside `while !self.busy() && !self.stopping && !self.releasing {` (630); `busy()` is `self.flight.running().is_some()` (338-340), and `live()` (693-699) is `self.flight.running().map(...)`, so `live` is empty every time. `releasing` stays set until `Input::Released` (559), and `pump`, `next_timer` (355) and dispatch all wait on it, so no in-charge program starts while a release is pending. An abandoned worker's program may still run (`charge.rs` 64-72, `abandon` takes `running`), but it is not in `live` either. The shell is the only consumer: `shell.rs` 475-480 matches `Effect::Release { … live }` and 592-596 converts it, `let live: Vec<Tag> = live.iter().copied().map(tag_of).collect();`, for `Store::release` (store/mod.rs 487), whose filter is `tags.retain(|tag| live.contains(tag)); tags.is_empty() && pending.report(carried).is_none_or(…)` (496-501): every tag list is emptied at every release. Nothing else reads the tags: `grep -rn '\bTag\b\|tag_of\|tag_node\|tag_anchors\|next_tag\|\.tag()\|tags_anchor'` over `crates/`, `xtask/`, `uia-facts/` finds only the writers (`store/mod.rs` 252-260, 666, 763-863; `worker.rs` 242; `mod.rs` 338-344), the `cfg(test)` `next_tag` and `tags_anchor`, and tests. The list became always empty with `93b2974c` (2026-11-16, "Remove the outpost's deadlines, moved-on rule and hang record"), which added that test.

What goes: `Tag`, `add`, `tag_node`, `tag_anchors`, `Nodes.generation` and `request: AtomicU64`, `Nodes::tag`, `shell::tag_of`, `Store::next_tag` and its `requests` counter, `Reducer::live`, `Effect::Release.live` and the `live` parameters; `State.nodes` and `State.anchors` become sets (their keys still say what the store holds: `pending.forget` reads `state.nodes.contains_key`, 532-535). ## 4. Questions for Dickson

**Q1.
