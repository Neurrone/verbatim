# Who decides which backend speaks a focus: the outpost's one verdict and its gap

Status: decided by Dickson on 2026-10-30: candidate B, as revised here, built as the rework's step 5 fix. Its proposed text is applied to [the focus pipeline rework](focus-pipeline-rework.md), which holds the current statement, with the final review's three fixes: a verdict judges no event observed before its probe began, the window keeping its previous entry for those; the gap read takes the foreground thread's focus window again with `GetGUIThreadInfo` after `GetFocusedElementBuildCache`, in place of judging the found element's own window, which a proxied list item does not have; and no notice is sent for a listener read the outpost drops, the held elements' cost being stated until step 11. Also decided: the restamp only moves forward and is made after the acceptance, front, repeat and readability tests and before the window's verdict; an abandoned worker's timed-out probe is still kept as unknown; the 3-second probe bound and the 500 ms keep from the probe's end stay. The decisions are listed last, under "Decisions for Dickson", as they were put to him.

## In short

B holds, revised in five places. The listener makes no backend verdict, as Dickson decided on 2026-10-30, so nothing it judges decides what is spoken. The gap record takes the stamp of each later copy it would have opened for, and of each foreground change into its window, so the gap's read after a return carries the return's stamp and is not dropped as stale. A drop for no window above the sender keeps main's own stamp, so a new window's first focus is read in both orders. A recovery read judges the window of the element it found as well as the focus window. And an abandoned worker records no verdict, so no verdict is applied retroactively to a focus judged before it.

The NVDA parity claims are corrected: NVDA cancels its main thread's probe only during freeze recovery (`nvda/source/watchdog.py` 151 to 232), so its two threads' probes disagree only then or when a window's provider changes between them. With that, B speaks a focus twice in two cases, both NVDA's, and once in one case where NVDA, in freeze recovery, speaks it twice.

The rules of B:

- One verdict per window, the outpost's. Every event of an application is judged for its backend by its outpost's verdict for the window NVDA judges it on, as that verdict stood at the event's observation, whenever the worker handles the event.
- The listener judges no backend. It reads every UIA focus that passes NVDA's checks, except that it skips the read when the sender's nearest window's class is on NVDA's MSAA class list, the outpost's own table and code. The outpost alone judges each read's window by its verdict, and drops a read in a window it judges not UIA.
- The gap record is the outpost's, in its intake. It opens only for a copy the worker dropped because its verdict said UIA, takes the stamp of each later such copy and each accepted foreground change in its top-level window, and is answered by the answer the listener sends with each UIA focus's outcome; the answer is final. Its one-second bound is a threadpool timer in the outpost.
- The outpost's one recovery read, the gap's read (at the bound, or at once after a drop for no window), goes through UIA only, is made once, and judges both the focus window and the window of the element it finds.

## Terms

- A copy is one focus `WinEvent` of an application. Both the listener's desktop-wide hook and the outpost's own hook receive it; only the outpost's handling counts.
- The record is the gap record: the wait, after a copy the outpost dropped for UIA, for a UIA focus that answers it. At main it is the listener's (`crates/verbatim-outpost/src/gap_record.rs`); under B it is the outpost's.
- An outcome is what the listener sends for one UIA focus event: its read, or its drop with a reason.
- An answer is what an outcome says of the record (`gap_answer`, `crates/verbatim-outpost/src/focus_read.rs` 638): it answers a copy in one top-level window, it answers a copy in any window, it has the focus read at once, or it leaves the record open.
- A class-list skip is the listener's drop of a UIA focus whose nearest window's class the shared class verdict (`arbitration.rs`, `classify`, 303) calls MSAA: on NVDA's MSAA list (`badUIAWindowClassNames`, `nvda/source/UIAHandler/__init__.py` 109 to 133) and not on the UIA list or under a shell window, with M5's extension tables added to both lists when they exist.
- A verdict drop is main's listener drop of a UIA focus on its own probed verdict (`Judged::DroppedOnVerdict`). B removes it.
- A keep is how long a verdict is kept: UIA for the window's life (decision D15), not UIA for 500 ms from the probe's end, unknown for 500 ms from the probe's end.
- A restamp is the record taking a later event's observation and window while it stays open, its bound unchanged.
- T, C and M are windows of one top-level window: T is the top-level window a copy names, such as Windows Terminal's `CASCADIA_HOSTING_WINDOW_CLASS` window, on NVDA's UIA list; C is a child window on no list, judged by the probe, such as the `Windows.UI.Input.InputSite.WindowClass` window that answered Windows Terminal's probe with a provider in `experiments/a-new-connection-fails-while-another-processs-remote-operation-is-queued/wt-launch-fast/listener.log`; M is a child window with no UIA provider, judged MSAA by the probe.

## The invariant and what is decided

The invariant (Dickson, 2026-10-29) is one verdict per window, as NVDA's, so that Verbatim speaks a focus twice only where NVDA does. NVDA keeps one cache per window in `isUIAWindow` (`UIAHandler/__init__.py` 1368 to 1380), stamped before the probe and kept half a second for either answer. Its MSAA path judges the event's own window (`IAccessibleHandler/__init__.py` 577); its UIA focus path judges the sender's nearest window (`UIAHandler/__init__.py` 887, through `isNativeUIAElement`, 1516 to 1545); its property and automation event handlers redirect an event whose sender is the focus to the focus object before any native check, and judge only other senders by their nearest window (1008 to 1020 and 808 to 819); its walk up a chain chooses each window's API by the same cache (`NVDAObjects/window/__init__.py` 319 to 330, through 115).

NVDA's probe on its main thread runs through `watchdog.cancellableExecute` (`watchdog.py` 406 to 425) and is cancelled only by freeze recovery (`_watcher` and `waitForFreezeRecovery`, 151 to 203), which starts once the core has not reported alive for 10 seconds, or for 0.5 seconds when the foreground thread has no focus window, a system menu is active while NVDA's focus is not in it, or the foreground window or its focus thread is not that of NVDA's focus object (`_shouldRecoverAfterMinTimeout`, 206 to 232). A cancelled probe is taken as not UIA (`UIAHandler/__init__.py` 1283 to 1286). On any other thread, the UIA handler's included, `cancellableExecute` calls the probe directly (418 to 420), so that probe is never cancelled and waits for `UiaHasServerSideProvider` itself. NVDA's two paths can probe one window at once, the second finding no cache entry until the first returns, and so keep different answers only when freeze recovery cancels the main thread's probe or the window's provider changes between the two probes.

Decided:

- Candidate B, the outpost owning each window's one verdict and the gap record (Dickson, 2026-10-29).
- The listener makes no backend verdict (Dickson, 2026-10-30). It reads every UIA focus that passes NVDA's checks that need no call into the application (the acceptance test against the foreground window, the console window's own focus, Core's hidden frame) and the sender's keyboard focus read live, with NVDA's hung-window and duplicate tests as now. It skips the read only on a class-list skip, a function of the window's class names that both processes compute with one table and one function, so they always agree on it; M5's extension tables, which add to the class lists, are reloaded by both. Its arbitrator and raw probe go, and so do verdict drops and the outpost's read after one. The outpost alone judges each listener read's window and drops the read in a window it judges MSAA. The listener's reads in MSAA windows off the class lists, about five calls on held elements each, are an accepted cost, not measured.

## Candidate B as revised

### The one verdict

- The outpost judges a window with the class lists, then the raw probe, then the post-probe class checks (`crates/verbatim-outpost/src/arbitration.rs`, `decide`, 519). Reason: this is NVDA's `_isUIAWindowHelper` (`UIAHandler/__init__.py` 1206 to 1300) as Verbatim already ports it.
- It keeps UIA for the window's life (D15), not UIA for 500 ms from the probe's end, and an unknown as not UIA for 500 ms from the probe's end. Reason: D15 spares a probe per focus change in every UIA window not on the class lists, and a keep timed from the end spares a second three-second probe of a busy window within half a second of the first; both keep a verdict at least as long as NVDA's cache, which is stamped before its probe, so Verbatim re-probes a window, and changes a verdict between two events, no more often than NVDA.
- A kept verdict is compared with the event's observation stamp: it judges every event observed before its keep ended, however late the worker handles it. An entry with no event, such as a focus-now query, is judged at its start. Reason: NVDA judges each event as it arrives, so the two events of one focus, at most 25.5 ms apart, meet one cache entry, while the outpost may handle a listener read seconds after its observation. The renewal of a "no" at an entry's end (`Arbitrator::renew_probes_since`, 276) and the entry's own record of a timed-out probe (`timed_out_here`, `begin_entry`) go, since every lookup in an entry then compares with the entry's one observation.
- A verdict is recorded only by the worker in charge. A probe that returns on an abandoned worker (`worker.rs`, `WatchState`, 95 to 118, whose abandoned threads run on) records nothing, its generation checked under the arbitrator's lock as the outpost checks it before publishing. Reason: the cache keeps one entry per window, which a new verdict overwrites (`record_probe_at`, 219 to 226); with the worker handling events in observation order, only an abandoned worker can record a verdict, observed for no event in order, between a focus's two judgements, and that verdict would be applied to the later judgement retroactively.
- Each event is judged on NVDA's window: the outpost's own MSAA events on the event's window (`worker.rs`, `msaa_focus`, 3438); the listener's read and the outpost's own UIA events on the sender's nearest window (`uia_focus`, 3585; the UIA event path, 2869 to 2872), the followed focus's own events by the focus's window, which a focus reported through UIA keeps UIA for its life, so the result is NVDA's redirect to the focus; and each window of a chain as it is built or converted (`read.rs`, `uia_chain_from_read`, 438). Reason: these are the windows NVDA's one cache judges.
- The outpost probes a window it has not judged before it reports a listener read there (Dickson, 2026-10-29).
- A backend override (`SupervisorToOutpost::SetBackendOverride`) is the outpost's. One that forces UIA also reaches the listener for that application, which then skips nothing by class, since its class-list skip would otherwise drop a focus the outpost counts.

### What the listener checks

- NVDA's checks, in NVDA's order (`focus_read.rs`, `judge_before_reading`, 1326): the sender's hung window; the native check reduced to the class-list skip, after the nearest-window lookup for a sender with no window of its own; the duplicate test against its kept element; the acceptance test against the real foreground window; the console window's own focus; Core's hidden frame; the sender's keyboard focus, read live. Then the read. Reason: the probe and the post-probe checks are the only parts of NVDA's native check that need a call, and they are the outpost's.
- The class-list skip is among NVDA's verdicts in `gap_answer`: it answers a copy in its top-level window. Reason: the outpost judges that window MSAA by the same function, so the focus is the window's MSAA copy's to speak, or nobody's, as in NVDA.
- Each drop carries its answer and the top-level window it is placed in: that of the nearest window it found, the sender's own from the event's cache, or none when it found neither. A read carries its window already, and the outpost places it.
- Out of time, nothing changes but the probe: the class list needs no call, so the read goes on from the event's cache where the listener's probe would have dropped it (`OUT_OF_TIME_BEFORE_JUDGEMENT` goes).

### The gap record in the outpost

- The record lives in the intake's shared state, under its lock. The worker opens it when it drops a copy because it judges the copy's window UIA, after the acceptance test and the readability checks; the copy comes from the outpost's hook, or is forwarded by the listener before the hook is in. A copy handled through MSAA opens none. Reason: the record then says exactly that this process dropped the copy for UIA, so nothing judges its window again.
- When the worker drops a copy for UIA, it first looks back. An answer for the copy's top-level window, or for any window, observed no more than 100 ms before the copy or after it, answers it, and nothing opens (`gap_record.rs`, 161 to 164). Otherwise a drop for no window above the sender observed no more than 100 ms before the copy or after it has the focus read at once, in the copy's place, stamped with the copy's observation (main's `last_no_window_us`, 137 and 214 to 225). Otherwise the record opens, with the copy's observation, window and top-level window, and its timer is set for a second after the copy's observation.
- While the record is open, a later copy the worker drops for UIA in the record's top-level window, or a foreground change the worker accepts into that window, restamps it: the record takes that event's observation and window, its bound unchanged. Reason: the record stands for the newest focus in its window that UIA has not answered, so a gap read after a return is stamped at the return, and an older focus's slow outcome does not answer a newer copy it says nothing of; keeping the bound keeps fast navigation from postponing the read.
- A copy of another top-level window of the application that the worker accepts, through either backend, or an accepted foreground change into another of its top-level windows, answers the record and cancels its timer; the copy then opens its own record if the worker dropped it for UIA.
- The intake applies each outcome's answer as it resolves the outcome's marker, with no wake of the worker. An answer for a top-level window, or for any window, closes the record when it was observed no more than 100 ms before the record's stamp, or after it, and in that window; it is also kept as the newest answer for its top-level window, or as the newest answer for any window. A drop for no window closes an open record it was observed no more than 100 ms before, or after, and the intake puts the gap's read in its marker's place; it is also kept as the newest no-window stamp. A drop for no keyboard focus or for being replaced leaves the record open (Dickson, 2026-10-21).
- An answer is final, whatever the worker later does with the outcome. Reason: the worker's drops of a listener outcome are NVDA's refusals (its verdict on the window, Core's hidden frame, from M5 a module's veto) or two refusals of Verbatim's own that are stated limits: a window another process serves (538bdca3), which NVDA reads through that process, and the intake's second hung test, which NVDA does not make and step 13 removes.
- The newest answers per top-level window are kept until a newer answer for that window replaces one, or the window is destroyed: the outpost's hook delivers the destroy event, on which the verdicts already forget the window. The answer for any window and the no-window stamp are one value each.
- The bound is a second from the first copy's observation, timed by one one-shot threadpool timer per outpost, set when the record opens and cancelled when it is answered; a restamp does not touch it. When it fires it pushes an entry into the intake, which waits behind every marker queued before it, so a UIA focus already being read decides first.
- When the bound's entry is handled with the record still open, the outpost makes the gap's read, stamped with the record's stamp, and the record closes.
- The outpost's idle answer waits while its record is open. The listener's idle answer no longer waits on records.

### The recovery read

- The gap's read, at the bound or at once after a drop for no window, is `read::focused_control_in` (`read.rs`, 952) through UIA only. It is refused with local calls when the system's foreground thread's focus window (`GetGUIThreadInfo`) is not the application's, is Core's hidden frame or cannot be read (`checked_focus_window`, 1055), or is a window the outpost judges not UIA, judged at the read. Reason: a focus in an MSAA window is that window's copy's to speak, and a focus in another application is that application's.
- After the read, the found element's own window, cached with the read (`UIA_NativeWindowHandlePropertyId` in the node's cache request), when it has one that differs from the focus window, is judged as a listener read's window, and the read is dropped when the outpost judges it not UIA. Reason: the focus can move into an MSAA window between the check and `GetFocusedElementBuildCache`, which then returns UIA's MSAA proxy for it, and that window's copy speaks it too; the check needs no call.
- The read is made once and is not retried after a failure or a refusal (Dickson, 2026-10-29). A read that finds the focus Core holds is dropped by Core's duplicate rule, its node coming from the same runtime id.
- There is no read after a listener's drop: the listener drops only on NVDA's checks, which the outpost would make too.

## The facts B splits

- The window's verdict: the outpost's alone, kept, probed and compared with each event's observation. The listener computes only the class verdict, a function of the window's classes with no keep, from the same table.
- The class tables: both processes hold them, loaded at start and, from M5, reloaded by both.
- The backend override: the outpost's; one forcing UIA reaches the listener.
- The UIA focus's outcome: the listener reads or drops it and computes its answer and placement; the outpost judges a read's window and applies every answer to its record.
- The copy: both hooks receive it; only the outpost's handling counts. The listener's copy is forwarded before the outpost's hook is in, and otherwise feeds only the listener's own stamps.
- The nearest window and its top-level window: the listener finds the nearest window and sends it; each process finds a top-level window locally with `GetAncestor`.
- Time: every observation is stamped by its observer from one microsecond clock (`verbatim_process::clock`), so the look-back, the restamp and the keeps compare stamps from either process.
- Whether a UIA focus is being read: the listener knows; the outpost sees its marker waiting in the intake, which holds every later entry, the bound's included.
- Whether the focus has gone to another application: the listener's hook sees it; the outpost learns it from the foreground thread's focus window at the read, and learns of a return from its own copies and foreground changes, with no message.
- NVDA's checks before a read: the listener makes all but the probe and the post-probe checks, which the outpost makes on the read's window.
